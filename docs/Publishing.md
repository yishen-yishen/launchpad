# 首次公开源码

本仓库的早期提交曾跟踪编译索引、生成的发行产物、宣传片原始帧及本机应用名称采样。当前版本已停止跟踪这些文件，并清理公开文档中的个人绝对路径；本地文件保留。

**这不会清除旧提交中的内容。不要仅提交新的 `.gitignore` 就认为现有历史已经清理。** Git 提交还包含作者邮箱；它与应用“关于”页的公开联系邮箱是不同的公开渠道。

## 不携带旧历史的发布方式

本次准备的 `build/PublicSource/LaunchDock-source.zip` 只包含整理后的源码、文档和最终宣传视频，不包含 `.git`、构建目录、安装包、编译索引、本机应用采样或原始录制帧。

1. 将源码包解压到一个新的空目录，不要覆盖原有仓库。
2. 在解压后的 `LaunchDock` 目录初始化新仓库，使用你愿意公开的提交身份：

```sh
git init -b main
git config user.name "YOUR_PUBLIC_NAME"
git config user.email "YOUR_PUBLIC_EMAIL"
git add .
git commit -m "Initial public source"
```

3. 推送到一个**新的空 GitHub 仓库**，或在另行确认历史清理方案后使用现有地址。不要直接对已有分支执行强制推送。
4. 将本地 `dist/` 中的 DMG 和 ZIP 作为 GitHub Release 附件上传。源码包不包含安装文件；README 中的 Releases 链接需要对应的发行内容。

本轮未改写本地历史，也未操作远程仓库。本地已有的 `origin/main` 跟踪记录属于旧历史；本轮没有联网核实远程仓库当前状态或可见性。如果旧内容已经对外发布，干净源码包并不能删除远程已有副本。
